## ⚡ 3. خط الإنتاج المتوازي فائق السرعة (Zero-Waiting Pipeline)

تنفيذاً لتوجيه البروفيسور زيزو (فويس 122) بمنع تعطل أي طرف في انتظار الآخر، يتبع النظام نمط **التدفق المتوازي (Pipelining)**:

| المرحلة | مهمة الوكيل الخارجي (FreebuFF) | مهمة وكيل التنفيذ المحلي (Antigravity) |
| :---: | :--- | :--- |
| **المرحلة 1: التحضير** | تفكيك مسار الـ API والترويسات من الـ HAR واستخراج حقول الـ Payload. | تجهيز مجلد المزود `providers/<slug>/`، وكتابة `definition.py`، وملف الاختبار التوصيفي `test_live.py`. |
| **المرحلة 2: الصياغة والتجربة** | كتابة منطق الدالة المستهدفة (`ask` أو `refresh`) وتجهيز الـ SSE parser. | بناء آليات الأمان المحلية: `FileLock` للحسابات، وحارس منع انفجار الموديلات غير البصرية `assert_text_only`. |
| **المرحلة 3: الدمج والاختبار** | الانتقال فوراً لتحليل الدالة التالية لتسريع الوقت. | استلام كود الدالة وتجريبه فوراً في التيرمينال وجمع الأدلة الكمية (Exit Code و Response Text). |
| **المرحلة 4: التغذية الراجعة** | في حال وجود عائق أو خطأ من السيرفر، يتلقى تقرير الخطأ ويقترح التعديل. | تعديل الكود جراحياً وإغلاق المهمة وربطها بالـ Gateway Server. |

## 🛡️ 4. بروتوكول اقتحام دالة التسجيل والإنشاء (`register`)

أكد زيزو وبولا (فويس 123 وفويس 124) أن دالة الـ `register()` هي أعقد وأصعب حلقة لما تحتويه من تريكات وتحديات (كابتشا، جافاسكريبت، بصمة متصفح، OTPs):

1. **تقاسم التخصص (JS & Browser Synergy):**
   - **Antigravity:** يستخدم أدوات المتصفح (SeleniumBase / CDP / Chrome DevTools) لفحص تدفق التسجيل، واستخراج الـ Tokens المشفرة من الـ LocalStorage/Cookies، وتحديد ما إذا كان الموقع يفرض كابتشا مرئية أو حماية Cloudflare Turnstile.
   - **الوكيل الخارجي:** يستلم البايلود المشفر وعينات استجابات الـ OTP ويفكك الـ Regex المناسب لاستخراج الأكواد بدقة فائقة.
2. **تمرير البارامترات الموحدة (Parameter Passing):**
   - يتم تبادل المتغيرات الصريحة فقط بين الطرفين:
     - مسار البروكسي (Proxy Endpoint).
     - توكنات الجلسة (Session Headers / User-Agent).
     - نمط بريد الـ OTP المؤقت ومحددات الـ DOM.
